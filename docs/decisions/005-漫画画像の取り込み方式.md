# 005: 漫画画像の取り込み方式

日付: 2026-07-27
状態: 採用

## 決定

記事の漫画イラストは GitHub Issue への画像添付を投稿口とし、
GitHub Actions が取り込んで `docs/YYYY-MM-DD/manga/NN.webp` に保存・紙面を再描画する。

## 理由

- **サーバー不要**: GitHub Pages は静的配信のみで、アップロードAPIを持たない。
  Issueの画像添付を経由することで追加インフラなしに画像を取り込める
- **iPhone完結**: ボタンタップ→Issue作成画面(タイトル・ラベル入力済み)→画像添付→送信
  の操作がiPhone Safariだけで完結する
- **お気に入り・継続ウォッチと機構共有**: 「ボタン→Issue起票」という操作感を統一できる
- **ローカルCLI (`python3 src/attach_manga.py <パス> <日付> <記事番号>`) はフォールバック扱い**

不採用にした案:
- VPSにアップロードAPIを立てる → インフラコスト・管理コスト増
- ローカルCLI方式のみ → iPhoneから完結しない

## 影響

- ローカルCLIは補助扱い。VPSへの移行判断を先送りできる
- 画像の有無は `brief.json` ではなく描画時の `manga/` ディレクトリ走査で判定する
  (毎朝のワークフロー再実行で添付が消えないようにするため)
- 1枚 300KB 目安に Pillow/WebP 圧縮して GitHub Pages の配信量を抑制する

## 制約メモ (2026-07-27 追記)

**GitHub モバイルアプリは Issue 作成 URL の `labels` パラメータを無視する。**
Safari から `https://github.com/.../issues/new?labels=manga&title=...` を開いても、
アプリにリダイレクトされた時点でラベルが消える。

対処: ワークフローのトリガー条件をラベルとタイトルの OR に変更した。
タイトルが `[manga]` で始まる場合もジョブを起動し、
取り込み成功後にワークフロー側から `gh issue edit --add-label manga` でラベルを付与する。
これにより iPhone → GitHub アプリの操作でもラベル無しのまま発火できる。
